# Sync+ / DiPlay CarPlay 仪表桥接

包名：`com.local.diplay.clusterbridge`，当前代码版本为 1.0。0.1.13 已于 2026-10-22 按用户停车授权以原签名覆盖安装并完成蓝牙媒体插拔验证；0.1.14 修正“去往”提示词，0.1.15 按用户最新要求改为去掉开头提示语并保留全部路名。仓库安装包同步更新为 1.0。较早实车验证和未解决问题见[四项故障排查记录](docs/FOUR_ISSUES_0.1.10.md)。界面为深色，最低 Android 8.0。保留仪表应用及车机助手的签名检查；其他车型和固件兼容性尚未验证。

## 1.0

按用户要求，将已验证的 0.1.16 功能版本号统一改为 1.0，versionCode 递增至 18，支持原签名覆盖升级。功能和现有设置保持。

## 0.1.16 CarPlay 通话仪表显示

新增默认关闭的“转发 CarPlay 通话姓名、号码和计时（测试）”。开启并连接 CarPlay 后，从下一次新通话开始读取 DiPlay 的实时通话记录，将拨号、来电、接通、保持和结束转换成 SYNC+ 电话显示格式；有姓名用姓名，缺少姓名时显示号码。挂断、断开、关闭功能或服务退出后清理桥接显示。蓝牙通话仍连接时交由原车显示。用户于 2026-10-22 反馈已手动安装测试成功；这属于用户实测反馈，不代表其他车型或固件均已验证。

通话内容仅在内存和本机辅助组件管道中使用，不进入桥接偏好、状态文本或日志。本功能需要本车已有的本地 ADB 和 `su 0`，只使用仪表电话显示属性，不调用接听、挂断或音频路由。原有道路和蓝牙设置保留。详见[通话显示适配说明](docs/CARPLAY_CALL_DISPLAY_0.1.16.md)。

## 0.1.15 去掉提示语，保留全部路名

“仪表道路文字”保留“保留原文”和“去掉导航提示语（保留全部路名）”。后者将 `去往 A B` 显示为 `A B`，将 `去往 八一路 洪山侧路` 显示为 `八一路 洪山侧路`，保留道路之间的空格，不再截成第一条路，也不添加逗号。已有第一条路或旧逗号设置自动转为这个模式；原文设置和首次安装默认值保留。

仅去除开头独立的提示词，完整保留后面的道路文字和多词英文路名。空白沿用既有规范化规则，缺少道路时沿用原占位。详见[提示语显示规则](docs/ROAD_PROMPT_ONLY_0.1.15.md)。

## 0.1.14 第一条路提示词修正

“仪表道路文字”仅保留“保留原文”和“始终只显示第一条路”。第一条路模式跳过独立的“去往”“进入”等提示词，例如 `去往 八一路 洪山侧路` 显示 `八一路`；只有提示词而没有路名时显示原有缺失占位。原文模式保留完整内容。

用户实测逗号也会乱码，因此移除逗号模式，已有 `comma` 设置在服务启动时转为第一条路，发送端同时兼容旧值，更新后不会继续加入逗号。这个改动修正显示规则，不据此认定仪表乱码的底层原因已经解决。详见[修正与验证记录](docs/ROAD_PROMPT_FIX_0.1.14.md)。

## 0.1.13 插入 iPhone 后管理蓝牙媒体音频（本地实测）

“转发设置 → 插入 iPhone 时关闭手机蓝牙媒体音频”默认关闭。启用后，车机在 USB 设备清单中识别到 Apple 厂商、产品名称为 iPhone 的设备，就保存所选手机原来的媒体设置，关闭该手机的蓝牙媒体音频并断开其媒体连接。默认保留蓝牙通话；另有默认关闭的“同时关闭蓝牙通话连接（可选）”。触发不等待 CarPlay 就绪；即使退出 DiPlay，只要 USB iPhone 仍插着，也保持所选连接关闭。

通话选项需同时开启上方的插入 iPhone 功能。它单独保存和恢复所选手机的原通话设置，关闭该选项不会恢复仍需关闭的媒体设置。正在通话或无法确认通话空闲时暂缓断开通话连接，不发送挂断命令。

拔出 iPhone、关闭此开关或正常停止桥接服务时恢复原来的媒体开关。原本已关闭的保持关闭；原本媒体已连接的，恢复后请求回连一次，是否立即连接由系统决定，不发送播放命令。USB 连续缺失至少 3 秒才恢复，常规检查约每 2 秒一次，短暂重新识别不会立即反复切换。识别结果不明时等待，保留待恢复记录。

“蓝牙手机”可指定 iPhone 的蓝牙配对；默认自动模式仅在一台已配对设备时执行。USB 和蓝牙地址不能直接互相匹配，多台配对时需明确选择。USB 只读取设备标识，不申请 USB 访问权限，不打开或占用设备。iPad、U 盘等不触发；多个 USB iPhone 或 Apple 设备名称缺失时不新执行操作。

仅接入 Android 8.0/8.1 的蓝牙媒体接收接口。新增普通 `BLUETOOTH` / `BLUETOOTH_ADMIN` 权限，不需要 root、无障碍或后台脚本。当前车机已核对插入时媒体关闭、拔出后媒体设置恢复且连接成功，默认通话保持连接；用户确认 CarPlay 正常播放及拔插恢复正常。可选通话开关的关闭与恢复已核对，未测试真实通话音频。详见[蓝牙媒体说明与验证记录](docs/USB_IPHONE_BLUETOOTH_0.1.13.md)。

## 0.1.10 导航同步与首次无声恢复

DiPlay 的导航日志和小组件不是同时更新。现在保留同一会话中最多 8 个真实导航状态，旧状态替换后最多保留 1.5 秒，仍须与小组件的方向和取整距离匹配；当前距离相同但转向编号不同的记录不会借用旧路名。缺失路名时最多等待 1.5 秒，不因新数据而无限延后。导航发送合并至最多每秒 2 次，相同内容每秒保活一次，待发送回调最多一个。导航原有 5 秒无更新超时保留，音乐没有周期重发。

道路文字中的 Unicode 空格统一为普通空格，去除不可见格式控制符；不猜测或删除原文中的问号、替换符。停车测试中，普通空格和 U+2005 空格都未复现照片的乱码，较长双道路文字出现截短。因此不能把照片中的乱码认定为已修复。

新增“首次开机无声时恢复一次”，默认关闭。需通过 ADB 单独授予 `DUMP` 系统诊断读取权限，并授权使用情况访问。启动检查最多持续本次 Android 开机后的 30 分钟，正常获得媒体焦点后立即结束。应用在后台读取 `audio`、`media_session` 快照，确认原车待机已退出、主／导航焦点栈及车辆音频资源为空、当前 DiPlay UID/PID 的媒体音轨正在播放且存在对应焦点申请、媒体按键仍交给 DiPlay，同时核对 CarPlay 前台、非通话、非静音等条件，才发送一次暂停；收到暂停之后更新的小组件回执，才继续播放一次。暂停回执最多等待 4 秒，次数在发送前按 `boot_count` 保存，每次开机最多一轮。其他音源、通话、前台变化、已获焦点或无法确认时不执行恢复。

音乐单独播放时，小组件可以长期不刷新，所以恢复不沿用导航的 5 秒时效；是否仍在播放以当前系统音轨核对。快照读取最多只有一个后台任务，最短间隔 2 秒，每项诊断最多约 2.5 秒、128 KiB，原始快照不落盘。`DUMP` 是可读取系统服务状态的持久诊断权限，代码仅请求音频及媒体会话两项；关闭恢复开关会停止相关读取，权限本身需另行撤销或卸载。它不自行请求音频焦点或调整音量。系统负责将媒体按键交给当前媒体会话，不同固件仍需验证。接口参考 [Android AudioManager](https://developer.android.com/reference/android/media/AudioManager#dispatchMediaKeyEvent(android.view.KeyEvent))。

本车 2026-10-19 完整关机、解锁黑屏播放、按启动的测试中，桥接在系统退出音频待机后仅发送一次暂停和继续，约 4.1 秒取得成功焦点回执，用户确认未按 Siri 而自动恢复声音。正常已获焦点时不触发也已验证；其他固件和更多启动场景仍需验证。

另新增默认关闭的“临时保存亮屏/音频诊断（本地）”：无需电脑保持联网，每次服务启动最多记录 45 分钟，两个文件总量最多 512 KiB，只保存屏幕、播放、音频模式及限定来源的焦点事件，不录音、不上传。目录为 Android 应用专属外部目录 `Android/data/com.local.diplay.clusterbridge/files/diagnostics/`，本轮测试结束已关闭。黑屏不一定等于 Android 的 `isInteractive=false`，无声恢复核对的是音频待机已退出、DiPlay 音轨仍活跃但未取得焦点。

0.1.10 发布时十组纯 Java 回归、APK 构建和签名校验通过；发布前停车测试未复现此前行驶约 30 分钟后的整机卡死。后续 10 月 19 日行车已捕获整机界面无响应，停止车机高德后用户确认恢复；不能把减少导航重复发送或本次道路文字补丁视为已经消除整机卡死。

除本地修复与模拟验证外，现车重启测试已记录到先打开 CarPlay、再退回主页，并由桥接在连接后约 5.37 秒自动恢复；用户确认未手动进入，导航和歌曲正常。其他用户的百度地图路名问题尚未取得其故障数据。详细证据和限制见 [本地排查报告](docs/LOCAL_AUDIT_0.1.9.md)及[实车测试记录](docs/VEHICLE_TEST_0.1.9.md)。音乐保持首次有效歌曲与实际变化时发送，导航仍使用原有 5 秒超时。

## 0.1.8 重装后恢复读取及剩余信息

0.1.8 同时修复 DiPlay 卸载再安装后的读取恢复：卸载会删除系统中的小组件及宿主记录，而桥接私有设置保留旧编号。旧版误把失效编号当作仍已分配，绑定失败后显示“尚未授权小组件”。现在先核对系统返回的本宿主编号清单，失效时重新分配并绑定，仍有效的编号继续复用。现有授权和转发设置保留；仅在小组件授权确实缺失时需要重新授权。

新增默认关闭的“林肯 SYNC+：剩余时间与里程”开关，需同时开启导航转发。通过车机助手配套仪表接收端的 `com.baidu.car.navi.REMAIN` 发送整型 `remainDistance`（米）和 `remainTime`（秒）。数据读取自 DiPlay 小组件已显示的剩余里程/时间，完整且有效时才发送，同一组合不重复发送。关闭或失效后，仅对本应用已发送的数据发一次 `0/0` 重置；用户已确认林肯功能通过实车验证。

该接口存在于本地留存的仪表程序，用户于 2026-10-22 确认林肯功能已验证，0.1.13 起取消实验性标签。不会新增音乐周期重发。详细字段、解析规则及验证边界见 [林肯适配说明](docs/LINCOLN_SYNC_PLUS.md)。

## 工作方式

DiPlay 的标准 `NavigationWidget` → Android `AppWidgetHost` → 本应用读取小组件中实际呈现的箭头、距离、道路、歌曲 → 定向广播到现有仪表程序。

本应用自行实现桥接代码，没有修改或重新打包 DiPlay，没有复制其私有认证材料，也没有替换仪表系统应用。没有无障碍和通知读取权限。声明前台服务、接收开机广播、日志读取、系统诊断读取、使用情况访问、普通蓝牙及网络权限；可选通话显示仅连接本机 `127.0.0.1:5555`，通过已有 ADB 和 `su 0` 启动固定的仪表显示辅助组件，不开启调试、不复制认证私钥、不修改系统权限，也不向外网发送数据。原有导航、歌曲及 USB 蓝牙管理不依赖此辅助组件。小组件绑定、日志读取及可选诊断读取需单独通过 ADB 授权。使用情况访问供默认关闭的自动进入和首次无声恢复功能确认前台页面。USB iPhone 媒体控制不依赖使用情况授权或导航转发开关。

0.1.4 增加路名回退：本次百度地图的 iAP2 数据未提供专用的“当前路名”和“转向后的路名”字段，但提供了 `0x5202` 参数 2 的完整导航说明，其中包含道路文字。DiPlay 0.2.19 没有把这个说明填入小组件，所以仪表收到空路名，显示为 `null`。

小组件有正常路名时，优先使用小组件。路名为空时，桥接读取 `xcertplay-usb` 标签的日志，并检查来源 UID 是否为当前 DiPlay，按进程、会话、转向编号缓存说明。只有当前导航状态、方向和取整距离均与小组件匹配，且导航状态不超过 15 秒，才把这段真实说明作为仪表道路文字。默认保留规范化后的导航说明；可选择仅在最终输出时去掉开头提示语并保留全部路名。没有可用数据时显示“道路名称未提供”，避免把空值显示为 `null`。

日志读取权限可以访问系统日志；导航读取命令只选择 DiPlay 传输、DiPlay 媒体焦点和系统焦点三个标签。导航解析只接受当前 DiPlay UID 的导航记录，开机无声恢复只接受当前 DiPlay UID 和系统 UID 的匹配事件。导航解析不把原始日志写入文件；临时音频诊断开启时，另外按上限保存限定来源的焦点记录。不上传。日志进程随桥接服务停止。

0.1.5 起在本应用私有偏好中缓存解析后的转向说明。0.1.9 起恢复还要求 DiPlay UID 和系统 `boot_count` 一致；无法读取开机编号时不恢复磁盘缓存，避免跨开机 PID 复用导致错用路名。恢复不恢复“导航有效”的判断；必须重新收到匹配进程、转向编号、方向和距离的新状态后才能使用。拒绝超过 24 小时的缓存，导航结束或断开时清除相应记录。

箭头通过当前安装 DiPlay 的同名 drawable 渲染结果匹配，资源 ID 在运行时读取。DiPlay 后续更新保留这些小组件名称和显示规则时，可以继续使用；接口变化时可能需要更新桥接应用。未知箭头或距离解析失败不会被当成直行指令。导航小组件超过 5 秒不更新时，停止本应用开启的导航。

## 首次连接与歌曲推送

音乐转发开启后，第一次从 DiPlay 小组件读到有效歌曲就推送一次；之后只在歌名或播放/暂停状态实际变化时更新。读取同一首歌不会反复推送；没有周期重发，也没有启动阶段的清空/回填。断开或关闭转发时仍清除本应用开启的音乐显示；重新连接后可推送新的首次歌曲快照。

“连接后停留在 DiPlay 时自动进入 CarPlay（一次）”默认关闭。启用并授予使用情况访问后，从读到有效连接开始观察 90 秒。等待至少 3 秒，确认 DiPlay 入口 Activity 连续停留约 2 秒后，调用小组件原有点击动作，每次连接最多请求一次。

首次开机可能先短暂显示 CarPlay、随后退回入口，因此仍保留连接初始检测窗口。自动进入一旦请求就结束本次检查，即使入口不可用也不重试；后续返回首页不会再次自动进入。未请求过时，若 CarPlay 已连续在前台显示 10 秒，也结束检查，避免把手动返回首页当作故障。其他应用前台、锁屏、灭屏、权限缺失或无法确认前台时不跳转。同次连接内反复开关功能或补回权限不会重置已使用的机会；断开后重新连接才开始新一轮。

DiPlay 主页和设置页共用 `DiPlayActivity`，外部应用只能识别 Activity，无法精确区分内部页面。若希望新连接后留在 DiPlay 设置页，请关闭自动进入。此功能辅助处理入口停留，不修改 DiPlay 内部的启动逻辑。Android 10 及更新版本还可能限制后台启动界面，当前未实测。

在桥接页面点“授权自动进入 CarPlay”，在系统的“使用情况访问”中允许本应用；定制车机没有授权页面时，可在停稳后用 ADB：

```sh
adb shell appops set com.local.diplay.clusterbridge GET_USAGE_STATS allow
```

该授权供自动进入和首次无声恢复确认前台，音乐文字推送不需要它。建议授权并开启后重新连接一次 CarPlay。应用仅在相应检查窗口内读取本次开机事件，后续增量读取，并在内存保留最新前台状态，避免主页停留超过一分钟后被遗漏；不保存或上传应用使用历史。

0.1.9 的本地构建、签名和六组回归测试已通过；现车已验证 Android 重启后首次连接时的主页回退与自动恢复，观察窗口内仅请求一次跳转。整车断电冷启动、休眠恢复及其他固件仍待验证。导航原有的 5 秒超时行为保留。

## 使用

1. 在车辆停稳时安装 APK，授权小组件。
2. 在 DiPlay 中连接 CarPlay，播放音乐并设置导航。
3. 打开“CarPlay仪表桥接”，确认状态中出现真实歌曲、道路、距离和动作。
4. 勾选导航和/或音乐转发，并在仪表上核对显示。
5. 使用原车百度/高德/QQ 音乐前，关闭本应用对应转发，避免两个来源互相覆盖。

首次安装的转发开关默认关闭；覆盖更新保留已经选择的导航和音乐开关。打开应用会启动前台读取服务，退回 DiPlay 后仍可读取。

0.1.2 默认开启开机自启动：系统完成启动后，在后台启动桥接前台服务，不弹出界面；覆盖更新本应用也会恢复读取服务。开机早期小组件暂不可用时，每 10 秒重试绑定。CarPlay 连接后才会转发有效内容。界面中的“车机开机后自动启动桥接”可关闭此行为。

停止按钮会关闭转发并停止当前服务，正常停止时会清除本应用开启的导航及音乐文字；它不改变开机自启动开关，下次开机可能启动读取，但不会自动重新勾选已关闭的导航或音乐转发。系统强杀、断电时无法保证执行清理；导航源本身不更新时由 5 秒超时处理。只有已启动的桥接进程能执行该超时。

开机自启动依赖系统发送 `BOOT_COMPLETED`，车机仅休眠再唤醒时不一定发送该事件。系统设置里的“强行停止”会阻止系统广播拉起应用，需手动打开一次恢复。车型定制的进程清理策略及休眠恢复需要另行实测；本应用没有改动车机电源策略。

ADB 安装和绑定：

```sh
adb connect <车机IP>:5555
adb install -r DiPlayClusterBridge-1.0.apk
adb shell appwidget grantbind --package com.local.diplay.clusterbridge --user 0
adb shell pm grant com.local.diplay.clusterbridge android.permission.READ_LOGS
adb shell am force-stop com.local.diplay.clusterbridge
adb shell am start -n com.local.diplay.clusterbridge/.MainActivity
```

Android 8.1 上首次授予日志权限后，需要按以上步骤重新启动桥接进程，使它获得 `log` 权限组。只重启读取服务可能不够。后续覆盖更新会保留授权；该流程不会重启或修改 DiPlay。

只有准备开启首次开机无声恢复时，才需要额外授予系统诊断读取权限；普通导航和歌曲转发不需要该权限。此权限持续到撤销或卸载，关闭开关只停止读取。当前 SYNC+ 固件允许通过 ADB 授予，其他系统可能拒绝，应用此时不执行恢复：

```sh
adb shell pm grant com.local.diplay.clusterbridge android.permission.DUMP

# 不再使用时可撤销；导航和音乐文字转发仍可工作
adb shell pm revoke com.local.diplay.clusterbridge android.permission.DUMP
```

退出和卸载：先打开应用，点击“停止并关闭转发”，再卸载。

```sh
adb shell appwidget revokebind --package com.local.diplay.clusterbridge --user 0
adb uninstall com.local.diplay.clusterbridge
```

## 显示限制

- 距离是小组件已经取整的显示值，不能恢复原始精确距离。
- 环岛显示通用环岛箭头，不能恢复第几出口或车道信息。
- 小组件歌曲是已合并的文字，作为标题转发；艺术家不单独拆分。仪表程序可能截短到 19 个字符。
- 不转发缺失的经纬度、到达时刻、歌曲进度/时长。0.1.8 的剩余总路程和剩余时长仅在林肯适配开关开启且数据完整时发送；数值来自小组件显示，已经取整。
- 默认仅转发音乐文字及状态；启用首次开机无声恢复后，在匹配故障条件时额外发送一次暂停/继续命令。本应用不请求音频焦点，也不调整音量。
- 音乐更新依赖 DiPlay 的歌曲/连接状态回调，暂无独立的进程死亡检测。异常退出而没有断开回调时，歌曲可能暂时保留。
- 两个应用同时向仪表发送信息可能互相覆盖。仪表没有提供可验证的来源仲裁接口，需关闭不使用的转发来源。
- 本次测试依据当前安装的 DiPlay 0.2.19。源码主分支仅用于理解公开小组件接口，实际解析取自设备当前资源。
- 日志回退依赖 DiPlay 现有诊断标签和格式，目前验证的是有线 CarPlay。未来 DiPlay 若关闭或改变这些日志，正常小组件路名仍可用，日志回退则可能需要适配。
- 如果启动桥接时，系统日志已清掉该转向的说明，必须等待新的转向说明，或在停稳时重新开始导航；程序不会复用没有匹配依据的旧路名。
- 日志回退输出的是完整导航说明，仪表自身仍会截短较长的文字；这不是恢复百度地图的全部道路/车道信息。

## 源码构建

需要 JDK 17 或更新版本、Google Android SDK 平台 35 和构建工具 36.0.0。应用仍编译为 Java 8 字节码，最低 Android 8.0、目标 Android 9。

```sh
# 不依赖 Android SDK 的协议、导航日志、首次连接及剩余信息测试
./test.sh

# 先安装对应的 Android SDK 包，再设置本机路径及自己的签名配置
export ANDROID_SDK_ROOT=/path/to/android-sdk
export JAVA_HOME=/path/to/jdk
export BRIDGE_SIGNING_KEY=/private/path/to/signing.jks
export BRIDGE_KEY_ALIAS=bridge
export BRIDGE_STORE_PASSWORD='your-store-password'
export BRIDGE_KEY_PASSWORD='your-key-password'
./build.sh
```

编译输出为 `build/DiPlayClusterBridge.apk`。构建不会自动创建签名密钥；签名私钥不在仓库中。使用其他密钥构建的 APK 无法直接覆盖本仓库发布的 APK。维护者后续发布会继续使用原签名，保留覆盖更新能力。

## 本次确认的接收协议

目标包：`com.baidu.xiaoduos.instrumentcluster`。

- `com.baidu.car.navi.STATE`：字符串 `state=TRUE/FALSE`。
- `com.baidu.car.navi.INFO`：字符串 `name` / `nextRoadName`，整型 `distance`，单位米。
- `com.baidu.car.navi.REMAIN`：整型 `remainDistance`（剩余米数）/ `remainTime`（剩余秒数）；0.1.8 实验开关默认关闭，林肯显示待验证。
- `com.baidu.car.radio.notify.PLAY_INFO`：`title` / `artist` / `album_name` / `source_name`，整型 `source_type=1`，布尔 `is_playing`。
