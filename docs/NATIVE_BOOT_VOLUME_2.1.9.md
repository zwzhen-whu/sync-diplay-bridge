# 2.1.9：原车开机音量

本版本最初在本地实现、检查与打包。发布时用户确认 2.1.9 已在本车实车验证，开机首次播放音量和关闭后的原厂音量参数恢复两项均已确认。此反馈不代表其他车型或固件已验证。

## 使用方式

打开桥接的“媒体音量记忆与开机音量”，选择“每次开机使用指定音量”，调整数值后保存。在本机已核对环境中，保存会同步原车媒体开机参数，核对写入结果后才显示成功；从下次整机开机生效，本次音量不变。升级保留现有选项；不会仅因升级而自动改写原车参数，需要进入设置保存一次。

选择“关闭”或“记住上次媒体音量”并保存，会先恢复接入前的原车启动参数。原值为空时恢复为空，不擅自写入猜测的 6 或 18。卸载前应先保存“关闭”；原车参数具有持久性，停止桥接服务和卸载 APK 不能替代恢复操作。

“记住上次媒体音量”沿用桥接的记忆方式，本轮没有把它改成固定原厂上下限。其他车机保留原有桥接恢复方式，不尝试写入未经核对的原车接口。

## 接入范围

- 只允许两个固定的 `Settings.System` 键：`on_volume_min_STREAM_MUSIC`、`on_volume_max_STREAM_MUSIC`。
- 实际写入前要求 Android API 27、`MEK-MX8Q` / `mek_8q`、当前用户 0、媒体量程 30、原厂键名方法匹配、桥接安装路径及签名匹配。
- 通过桥接现有的本机 `127.0.0.1:5555` 调试通道运行固定辅助程序；不获取新授权，不连接其他地址。通道或权限不可用时报告未完成，不能冒充同步成功。
- 调用固定参数的系统设置工具，不调用 `setStreamVolume`、`setOnVolumeMin/Max` 或音频路由修改接口，不重启 DiPlay，也不注入新的音频脚本。
- 微信语音小包、通话增益、地图脚本沿用 2.1.8。通话和地图无需为了此设置重开。

## 写入、恢复与去重

`NativeBootVolumeTransaction` 将第一次读取的两个原值保留为原始备份；更换目标音量不覆盖备份。变更前先持久化操作记录，再逐项写入，回读一致后提交。一次同步中的失败会尝试撤销；无法撤销时保留记录，供下次辅助程序启动恢复，不报告成功。

持久备份及撤销记录位于 `/data/local/bridge-native-boot-volume`，目录权限 0700、文件 0600、root 属主，有互斥锁；写入临时文件并同步后原子替换，随后同步目录。仅接受普通单链接文件。同步被中断时，辅助程序先撤销未提交变更，再处理请求。发现值已经被其他原车设置修改时不覆盖，保留备份并报告冲突。

应用先保存待同步请求，再执行操作，确认原车结果后提交界面选项。失去响应时保留待处理请求和状态，重开设置或桥接服务时可以继续核对；没有每秒查询原车参数的后台循环。

原厂接管得到确认后，桥接不再晚几秒重新设置媒体音量；只记录本次开机已经处理。参数或同步状态不一致时暂停重复恢复并显示待核对，避免覆盖用户已经手动调过的音量。

## 本地验证与后续边界

纯内存测试覆盖全部 0–30 档、原值不存在或部分存在、反复保存、更换目标、关闭恢复、备份写入失败、第二项写入失败、回读不一致、提交失败、写入中断、关闭中断、撤销失败、外部参数变化和通信断开。测试不访问 Android 设置、不连接 ADB、不发起电话。

构建另行运行现有检查，并核对签名、包名、版本与旧音频/地图资产。UI 已改成可滚动的设置页，保存期间显示进度，出错时保留页面；这些是最初打包时的本地检查结果。

发布前用户补充确认：本车开机首次播放音量及关闭后的原厂参数恢复均已实车验证。系统参数回读与扬声器播放时机是不同的检查；其他车型、固件及更多使用场景仍需分别验证。
