# 0.1.14 第一条道路与逗号模式修正

历史记录：用户随后要求保留双路名，0.1.15 已将“第一条路”改为“去掉导航提示语（保留全部路名）”。当前行为见 [0.1.15 说明](ROAD_PROMPT_ONLY_0.1.15.md)。

2026-10-22，本地更新，包名和签名沿用 0.1.13。versionCode 15。

## 问题与行为

用户实测“只显示第一条路”只显示“去往”；逗号模式会在“去往”和道路之间插入逗号，逗号也出现乱码。代码复现确认：首段规则的提示词列表漏掉“去往”，旧逗号模式则直接替换所有空格，没有区分提示词与道路。

按用户选择，移除逗号模式，仅保留以下两个选项：

| 选项 | 输入 `去往 八一路 洪山侧路` | 输入 `八一路 洪山侧路` |
| --- | --- | --- |
| 保留原文（首次安装默认） | `去往 八一路 洪山侧路` | `八一路 洪山侧路` |
| 始终只显示第一条路 | `八一路` | `八一路` |

第一条路模式跳过独立提示词“去往”，兼容普通与 Unicode 空白以及多个连续提示词。只有“去往”“请 去往”等提示而没有路名时，显示“道路名称未提供”，不把提示词作为道路。原文模式不剥离提示词。

已有 `road_display_mode=comma` 在后台服务启动时持久改为 `first`，即使持久写入尚未结束，发送端也把旧值解释为第一条路。界面同时按新规则显示当前选择，避免仍选中已取消的选项。原文与第一条路的已有选择保留。

处理仅作用于最终仪表道路字段。导航日志原文、路线匹配、箭头、距离、发送节流和歌曲策略沿用。0.1.13 已验证的 USB iPhone 蓝牙媒体与可选通话代码不改。

## 验证与边界

- 先用用户描述构造失败回归，旧版实际返回 `去往`，预期 `八一路`；修改后通过。
- 十四组回归通过，道路显示组含 128 项检查，覆盖遗漏提示词、Unicode 空白、仅有提示词、原文保留、旧逗号设置、后续道路更新、源匹配隔离和发送限制。蓝牙组 106 项断言继续通过。
- Android APK 构建和原签名校验通过。已在当前车机覆盖安装，versionCode 15，安装的 APK 与最终构建逐字节一致；原有蓝牙和日志读取权限保留。
- 现车短暂切换第一条路模式，当前真实源道路含“进入”提示，桥接实际输出只保留道路名称，模式切换正常；检查后恢复用户原有的原文选择。此项核对的是桥接输出，仪表实际字形仍需用户复测。
- 界面核对已无逗号选项。原文选择和可见的自启动、导航、音乐及林肯开关与更新前一致。最终安装及交付结果记录在本地 `inspection/2026-10-22/road-prompt-fix/`。

没有改用其他标点替代逗号；用户观察到的逗号乱码不等于已定位底层编码问题。本次只修正首段选择并停止程序添加逗号，不能保证其他来源的问号或仪表乱码消失。

仍按空白划分第一条路，不猜道路后缀或没有空格的提示前缀；例如 `进入八一路 洪山侧路` 保留 `进入八一路`，`Main Street` 会缩短为 `Main`。可切回原文保留完整文本。
