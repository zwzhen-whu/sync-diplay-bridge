# 插入 iPhone 后关闭蓝牙媒体音频

版本：0.1.13 / versionCode 14。已在当前车机覆盖安装验证，保留原包名与签名，仅本地使用。

## 行为

1. 在“转发设置”启用“插入 iPhone 时关闭手机蓝牙媒体音频”。需要时在“蓝牙手机”选择 iPhone 的蓝牙配对；自动模式仅支持唯一已配对设备。
2. USB 设备清单中出现 Apple `0x05ac` 且产品名为 `iPhone` 或 `iPhone …` 的唯一设备后，先持久保存所选配对的原媒体开关与连接状态，再关闭媒体开关、断开媒体连接。
3. 默认保留蓝牙通话；可另行启用“同时关闭蓝牙通话连接（可选）”，以同样的 USB 条件控制通话接收 `HEADSET_CLIENT`。两个连接分别保存和恢复原设置，关闭通话选项不会恢复仍需关闭的媒体。蓝牙总开关和配对关系保留，不发送暂停、播放或挂断命令。
4. 拔出 iPhone 并连续确认缺失至少 3 秒后恢复原媒体开关；关闭功能或正常停止服务也恢复。原来已关闭的保持关闭，原来媒体已连接的请求回连一次，不自动请求播放。

触发条件为 USB iPhone 在场。退出 DiPlay 或 CarPlay 尚未完成连接时，只要 iPhone 仍通过 USB 被识别，媒体仍保持关闭。蓝牙或无线 CarPlay 单独连接不触发。充电线不提供 USB 设备识别时无法触发。

通话选项默认关闭，依赖媒体主开关。准备断开通话连接前核对音频模式与当前蓝牙通话列表；通话进行中、响铃或无法确认空闲时先等待。未开启该选项且没有待恢复记录时不绑定或操作通话服务。拔出或关闭主开关时恢复两个连接各自的原开关；原本已连接的分别请求回连一次。

## 保护与限制

- USB 广播仅用于及时重新扫描；以真实设备清单为准，不信任广播携带的设备对象。每约 2 秒有一次兜底检查，后台蓝牙任务最多一个。
- 不申请 USB 权限，不打开 USB 设备或接口。Apple 产品名缺失、多个 USB iPhone 或设备清单读取失败时不开始新的关闭操作，也不据此恢复原设置。
- USB 没有可用的蓝牙地址映射。多台配对需用户明确选择；自动模式在本次已保存恢复记录后继续使用原目标，直到恢复完成。
- 当前只支持 Android 8.0/8.1；隐藏蓝牙接口或设置键不匹配、权限缺失时显示状态并停止相关操作，原导航/歌曲桥接继续运行。
- 使用普通 `BLUETOOTH`、`BLUETOOTH_ADMIN` 权限，不请求额外系统写设置、root 或无障碍权限。通过系统媒体服务修改设置，`Settings.Global` 仅用于读回核对，不直接写全局设置。
- 保存恢复记录成功后才开始修改。媒体断开最多请求 3 次，间隔至少 5 秒，必须读到媒体优先级关闭且连接已断开才显示“已确认”。
- 进程被强杀或整机断电时无法执行立即恢复；待恢复记录保存在应用私有偏好中，下一次启动并确认拔出后继续恢复。卸载会清除记录，卸载前应先关闭功能并确认恢复。
- 恢复时若发现媒体开关已经被用户或其他程序改成开启，不覆盖该设置。Android 此接口只接受优先级 0/100；原优先级 1000 恢复为开启 100，不声称恢复系统内部自动连接优先级的原始数值。
- 原连接恢复只发一次回连请求，连接成功及是否继续播放由车机和手机决定。此功能与已有的首次开机无声恢复是两个独立开关。

## 2026-10-22 证据

安装前只读基线：`MEK-MX8Q`，Android 8.1，桥接 0.1.12 / code 13，DiPlay 0.2.19。USB 报告包含 Apple `05ac:12a8`、产品名 `iPhone`。蓝牙有唯一配对手机，媒体接收服务 `A2dpSinkService` 和通话接收服务 `HeadsetClientService` 均为连接状态；对应媒体开关为开启。个人设备标识及原始快照只存于本地排查目录，不随交付包提供。

离线蓝牙/USB 测试共 106 项断言，覆盖识别、插拔去抖、原本关闭、重启恢复、持久保存失败、重试上限、恢复失败、手动改设置、更换目标及媒体/通话恢复记录隔离。十四组回归、Android 构建和原签名校验通过。现车安装的 APK 与最终构建的 SHA-256 完全一致。

用户确认车辆已停稳后，以原签名覆盖安装 0.1.13 / code 14，原设置和授权保留，并启用插入 iPhone 管理媒体。已取得以下实车证据：

- 连续拔插观察中，未插入时媒体优先级为 100；插入后变为 0，媒体服务断开，通话优先级保持 100。用户确认 CarPlay 持续正常播放。
- 可选通话开关开启后，通话优先级由 100 变为 0；关闭选项后恢复 100，期间媒体始终保持 0。测试后该选项恢复默认关闭；该项验证不包含真实通话音频。
- 用户反馈拔出后未立即恢复时，再次同步观察：USB iPhone 先消失，随后媒体优先级从 0 恢复 100，媒体服务从断开变为连接，通话全程保持连接。恢复包含至少 3 秒的 USB 缺失确认、约 2 秒的检查间隔和系统回连耗时；用户随后确认“可以了，正常了”。

原本关闭的设置不被误开启、故障及进程重启恢复已由离线回归覆盖，未在本次车机上逐项制造故障测试。其他固件、休眠恢复和真实通话中的延期断开仍需对应场景验证。

## 本车固件参数适配

本轮系统代码与实车日志确认：当前 SYNC+ 的 `BluetoothA2dpSink.setPriority(device, priority)` 将请求参数固定替换为 `100`。因此传入 `0` 时，系统媒体服务仍记录 `Saved priority … = 100`。初步测试把这个现象误判为自动重连；媒体连接在按原车顺序断开后可以保持断开，但媒体开关仍为开启。

适配代码将原始优先级通过已绑定的系统接口提交，媒体使用 `IBluetoothA2dpSink`，可选通话使用 `IBluetoothHeadsetClient`。服务继续检查本应用的普通蓝牙权限，设置后再读取系统值与连接状态确认。没有修改系统框架或增加系统写设置权限。原车设置界面的“先断开连接、再关闭优先级”顺序也保留。

用户已确认本轮曾手动断开手机蓝牙，因此该时段通话断开不能作为程序导致通话断开的证据。真实拔插、通话实际音频和连续播放的验证与配置开关读回分别记录。

## 代码与接口依据

- `BluetoothMediaGuard.java`：USB 清单读取、蓝牙媒体接口、持久恢复记录、后台执行与状态。
- `BluetoothMediaPolicy.java`：关闭与恢复顺序、去抖、次数限制。
- `IphoneUsbPresence.java`：USB 描述识别与不明确状态。
- Android 官方 [A2DP Sink 接口与设置支持提交](https://android.googlesource.com/platform/frameworks/base/+/ba12af516722bd559e19f9b3e8618dc4359e617b%5E%21/)：媒体接收优先级和 SettingsLib 的媒体开关路径。实际权限和行为仍以当前固件验证为准。
