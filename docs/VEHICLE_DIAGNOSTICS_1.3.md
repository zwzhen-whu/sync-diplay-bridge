# 1.3 车辆环境、音乐与导航诊断

本地开发版。替换旧的“临时保存亮屏/音频诊断”，保留独立的“首次开机无声时恢复一次”。启动诊断不会改变导航、歌曲、蓝牙和通话控制设置。此版本尚未在车机上验证公共下载目录导出及新的接收端采集。

## 给车友的操作说明

1. 车辆停稳后连接 CarPlay，在桥接中开启需要检查的导航、音乐转发。
2. 点 **开始诊断（3 分钟）**。第一次使用时，允许系统弹出的文件存储权限。拒绝权限时不会开始，允许后可重新点击。
3. 在 iPhone 高德中选择目的地，点 **开始导航**。只打开地图或预览路线不能采集导航指令。其他导航软件可按同样方式测试，在反馈中注明名称和版本。
4. 在 CarPlay 播放音乐，再切换一首歌曲。观察仪表的箭头、距离、路名和歌曲。可切回 CarPlay，采集会在后台继续；行车时请勿操作或查看诊断界面。
5. 约 3 分钟后自动保存，也可点 **结束并保存**。停止桥接会提前结束并尝试保存。
6. 界面显示具体保存路径，通知栏也会提示结果。在车机文件管理器的 **下载 → CarPlay诊断** 找到 `CarPlay诊断-日期时间-随机编号.zip`。
7. 将 ZIP 交给开发者，说明手机导航软件及版本、仪表异常现象和大致时间。日志含道路、歌曲文字，分享前可查看。

实时界面会根据缺少的数据提示连接 CarPlay、开启转发、开始真实导航、播放和切歌。无需每项都存在才允许保存。缺少数据会写入报告，不能把“未观察到”当作不支持或通过。

保存失败时保留应用内副本。检查文件权限和空间后点 **重新保存日志**，无需重新导航。采集中应用或系统中断时，下次打开会恢复已采集的部分文件并提示导出；中断之后的数据需要重新采集。私有目录最多保留最近 3 次采集，成功导出后只保留最近一次副本。公共下载目录中的报告由用户自行管理。

## 导出内容

ZIP 仅包含三个明确文件，不打包偏好、缓存、其他日志或应用数据：

| 文件 | 内容及上限 |
| --- | --- |
| `summary.txt` | 开始/结束时间和原因，设置、阶段计数、缺项、异常、队列丢弃、截断及分析提示 |
| `environment.txt` | 最多 128 KiB；型号/固件/API，桥接/DiPlay/仪表/助手版本与签名，权限、进程日志组、小组件绑定及资源、广播接收器、USB/蓝牙概况、音频只读快照 |
| `events.tsv` | 最多 1 MiB；毫秒时间、事件类型和内容，源导航参数、小组件文字及字符诊断、道路处理、等待/去重/门禁决策、广播目标/参数/提交结果、原车接收端白名单日志 |

系统音频/媒体会话快照在开始、每约 15 秒及结束读取。单项超时约 2.5 秒，内存上限 128 KiB，只保存解析后的焦点/播放/按键接收者结论，原始快照不落盘；未知格式标为未知。

源导航复用现有日志流，只接受开始之后、当前 DiPlay UID、`xcertplay-usb` 的 `0x5201/0x5202` 已知导航参数。通话帧 `0x4155`、帧原始字节及连接会话标识不保存。“收到帧”与“完整解析”分别统计。

原车接收端另启仅在诊断期间存在的读取器，接受当前仪表 UID、`NavPresenterImpl` 和 `MediaReceiver` 的已知导航下发/道路及音乐消息。前缀依据本地留存的原车反编译程序核对。排除同标签的家庭/公司地址、`IService` 电话日志、联系人、号码和电话控制标签。其他固件可能不输出这些消息；没有日志不等于没有接收。消息也可能来自其他导航/音源，须按时间和文字对照。

## 如何分析

- 应用、权限或小组件接口异常：优先检查环境文件。仪表/助手签名门禁未通过时仍会阻止转发，不放宽原校验。
- 有源帧但完整解析为零：检查参数格式、丢失/截断、是否从帧中途采集及 DiPlay 版本。
- 有源帧但无有效小组件指令：检查是否真正开始导航、距离/箭头识别、绑定和更新。
- 有有效输入但无分发：看开关、门禁、路名等待、更新过期和去重。音乐只在歌曲或播放状态变化时发送，因此提示切歌；不会为了诊断额外切歌或重复发送。
- 有分发提交：对照原车处理记录中的文字，定位接收后的截断/变化。仍不能据此确认仪表硬件显示正常。
- 广播接口没有显示确认回执。`sendBroadcast()` 返回只说明已提交给 Android；接收器注册只说明接口存在。HAL/硬件以下的最终结果需要人工核对。

诊断不录音、不上传、不改变音量/焦点/蓝牙、不注入测试导航，不自动开启转发或授予系统日志权限。其他已启用功能继续按原设置工作。

## 存储和线程

Android 8/9 请求 `WRITE_EXTERNAL_STORAGE` 后写公共 `Download/CarPlay诊断`，临时文件复制并同步后再改名，不覆盖报告。Android 10 及以上使用 `MediaStore.Downloads` 待完成条目，成功后公开；该分支尚未实机验证。依据 [Android 共享存储说明](https://developer.android.com/training/data-storage/shared/media)。无需 root、全部文件访问或联网。

同进程复用一个采集管理器，避免服务快速重启时并行导出或误恢复。文件和系统快照在一个后台线程处理，输入队列最多 512 条，丢弃计数写入摘要。结束后取消计时和原车日志进程，空闲线程回收。开始时保存会话目录，支持进程中断后的部分恢复。

## 本地验证与待测项

`VehicleDiagnosticTest` 覆盖操作提示、UID/时间/线程隔离、通话及家庭地址排除、接收与解析分开、分发与显示回执区分、旧数据过期、签名阻止、失败分发、UTF-8 字节上限、截断提示、ZIP 白名单及重建。完整回归还覆盖原导航、路名、蓝牙、通话和按键逻辑，通过数量见随包验证文件。

公共下载导出、后台自动结束，以及其他固件的权限和接收端格式仍需安装后停车实测，不能将离线通过当作实车已通过。
