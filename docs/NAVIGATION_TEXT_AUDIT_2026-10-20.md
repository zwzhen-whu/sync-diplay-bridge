# 道路文字代码排查与未发布补丁

2026-10-20。基线为已发布 0.1.10 的 b86aa81；本记录对应安装前的代码排查和验证，只修改道路文本规范化和导航日志状态，不改变权限、设置、音频恢复或歌曲转发。后续已按用户停车授权构建并安装本地 0.1.11，见[更新记录](VEHICLE_UPDATE_0.1.11.md)；尚未公开发布或完成真实路线显示验证。

用户反馈：含空格的“三环线 卓刀泉立交”间歇空白、问号或正常，随后“珞瑜路”也不显示；发生时界面和音乐仍流畅。本次没有这两段故障的原始源文字及接收日志，以下是代码缺陷与离线回归，不是完整实车复现。

## 确认并修正的缺陷

| 缺陷 | 原行为 | 补丁 |
| --- | --- | --- |
| 不兼容日志中的数字零 | DiPlay 0.2.19 的 opaque 格式化先尝试字符串，单字节零输出 `""`；助手不能识别直行类型零，也漏掉结束状态零 | 仅在已知 u8 数字字段把 `""` 识别为零，文本字段语义保持不变 |
| 拒绝非结束状态 3 / 5 | 助手只接受状态 1，与源状态机不一致 | 与源保持一致，0 / 2 结束；其他有效 u8 状态仍受会话、转向、距离、时效校验 |
| 首路详情误清后路 | 活跃在后续路口时，迟到的零号详情清除路线及同前缀其他详情 | 单独详情不清活跃后路；确认非零转向编号回到零时再隔离旧未来说明，候选也受时效约束 |
| 短暂空列表导致无法接续 | 立即丢失当前路由；下一条若只补列表和距离而无 State，则被拒绝 | 保留最多 3 秒的匹配状态；持续为空隐藏文字但保留新鲜上下文，恢复列表后可继续匹配；重复空列表不延后隐藏截止 |
| FIFO 淘汰当前和近期道路 | 64 条以外先删最早插入的说明，预发未来路口可能挤掉当前、紧接路口 | 保留 64 条硬上限，优先当前与 1.5 秒滞后引用，淘汰无关、已过及更远的预发详情 |
| 判空与最终清洗不一致 | 只有格式符的文字被当成有效路名，阻止真实日志回退，发送时却变成占位 | 共用规范化判空规则；诊断增加字面问号计数，保留真实问号及 U+FFFD |

上述状态修复主要影响小组件道路为空时的日志回退；非空源文字本身已含问号或替换符时，仍会保留它，不能把该补丁当作已经证明的乱码修复。收到结束、CLOSE、UID/PID/会话变化后仍不能借用旧来源的道路。

## 源码依据

按官方 v0.2.19 标签 e06a250219b2c2288948d8b4ad7203b417db0de1 核对：

- [Iap2FrameFormatter](https://github.com/shihabal3amri/DiPlay/blob/e06a250219b2c2288948d8b4ad7203b417db0de1/shared/src/main/java/com/shilapi/xcertplay/iap2/trace/Iap2FrameFormatter.kt#L148)：opaque 的先字符串后数字逻辑。
- [BydHudRouteState](https://github.com/shihabal3amri/DiPlay/blob/e06a250219b2c2288948d8b4ad7203b417db0de1/shared/src/main/java/com/shilapi/xcertplay/hud/BydHudRouteState.kt#L168)：结束状态及短暂空列表语义。
- [上游空列表回归](https://github.com/shihabal3amri/DiPlay/blob/e06a250219b2c2288948d8b4ad7203b417db0de1/shared/src/test/java/com/shilapi/xcertplay/hud/BydHudRouteStateTest.kt#L144)：3 秒隐藏及不重新发送详情的恢复。

较早留存的两份真实输入有 11 条被格式化成空引号的零状态、6 条状态 3，证明这些格式确实出现过。未在这些捕获中观测到直行类型零；这一项由官方格式化器和真实解析类的确定性回放证明，不能冒充本次行程的现场证据。

接收端的 INFO / nextRoadName、sendStreetName、CarService Java 字符串到 HAL 路径未见按空格分词或 24 字节固定缓冲。9 个 UTF-16 单元的双路名不会触发其 20 单元截断分支。车辆 HAL 以下的实现、其他导航来源是否同时写入仍缺现场证据。

## 验证

- 完整 `test.sh` 12 组通过，包含原有 10 组。
- `RoadNormalizationTest` 94 项检查通过；原始基线在纯格式符判空处失败。
- `NavigationStateContinuityTest` 13 组：原始基线 5 通过 / 8 失败，补丁后 13 通过 / 0 失败。
- 覆盖直行、迟到首路、超过 64 条预发、空列表恢复、重复空列表隐藏截止、候选过期、结束与来源隔离、方向距离校验。
- 代码排查阶段全部 21 个 Android Java 源文件编译及 D8 转换通过；后续用户授权的签名构建、安装和读回校验见单独更新记录。

同一 PID、连接会话和标识符内的路线重用仍有协议歧义。补丁依据已确认的转向选择和结束事件隔离，不靠路名内容推断路线代次。仍需停车时用真实输入核对源文字、助手输出与仪表接收内容，才能定位问号的产生层级。
