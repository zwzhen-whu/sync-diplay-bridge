# 0.1.12 双路名显示选项

以下为 0.1.12 的历史方案。2026-10-22 用户确认逗号也会乱码，并选择取消逗号模式；0.1.14 仅保留原文与第一条路，补充跳过“去往”提示词，旧逗号设置转为第一条路。当前行为见 [0.1.14 修正记录](ROAD_PROMPT_FIX_0.1.14.md)。

2026-10-20，本地候选，尚未安装或公开发布。本次用户明确要求在应用中选择半角英文逗号或始终只显示第一条路；保留原文作为默认与回退项。

## 在应用中选择

打开“CarPlay仪表桥接”，在“转发设置 → 仪表道路文字”选择一项：

| 选项 | 收到 `八一路 洪山侧路` 时的仪表文字 |
| --- | --- |
| 保留原文（默认） | `八一路 洪山侧路` |
| 空格改为半角英文逗号（测试） | `八一路,洪山侧路` |
| 始终只显示第一条路（测试） | `八一路` |

选择保存在原有应用设置中，后续每条道路均执行同一规则，不因是否出现问号而切换。重开应用与服务继续使用所选模式。无需重新授权或重启 DiPlay；有效导航切换时沿用最多每 500 毫秒发送一次的限制。可随时切回保留原文。

## 处理范围与限制

- 先沿用原有空白规范化，再替换空格或取首段，只在发送仪表前处理。小组件原文与日志状态不改，方向、距离及音乐转发策略不改。
- 第一条模式按空白分段；`进入 八一路 洪山侧路` 会跳过独立提示词而显示 `八一路`。不根据道路后缀猜测边界；`进入八一路 洪山侧路` 显示 `进入八一路`。
- 含空格的英文道路也会缩短，如 `Main Street` 显示 `Main`。它是显示兼容选项，不是任意语言的道路名称解析器。
- 缺少路名时仍等待最多 1.5 秒，再显示原有占位；不以“第一条”方式长期保留旧道路。后续 `珞瑜路` 正常替换当前文字。
- 已经出现在第一段的 `?` 或 U+FFFD 不会被猜测替换；逗号与第一条模式均不能恢复已经丢失的汉字。

## 已知原因边界

用户最新行车反馈：0.1.11 后普通路名持续空白未再出现；`八一路 洪山侧路` 仍在问号与正常之间跳变，故该问题尚未闭环。

检查留存的原车 `CarVendorInstrumentClusterManager` Java 源码，道路字段拼为 `SignalID:0x20;StreetName:<文字>;`；该层不以空格或逗号分词。不能推断仪表底层也支持所有符号，更不能据此确认空格是根因。

`八一路 洪山侧路` 为 22 个 UTF-8 字节，改半角逗号仍为 22；中文逗号版本为 24。该比较仅排除“半角逗号增加字节数”，不证明任意固定缓冲上限，也不保证仪表效果。

没有本次乱码发生时的源文字、助手输出与接收端同步日志，目前无法确认问号产生于 DiPlay 输入、另一写入源、CarService 以下编码还是仪表刷新。当前 ADB 不可用，仅进行本机代码、回归、构建及签名验证，未向车机发送任何内容。

## 离线验证范围

完整 13 组回归及 Android 构建通过，其中新增 `RoadDisplayModeTest` 的 122 项检查覆盖三模式、Unicode 空白、连续双路名、后续普通路、提示词、原始日志匹配隔离、切换触发发送及节流、缺失路名等待和已有乱码保留。完整验证结果与 APK 校验信息保存在工作区 `inspection/2026-10-20/dual-road-comma/`；测试通过仅证明本地逻辑，不代表实车显示通过。
