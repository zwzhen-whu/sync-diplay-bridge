# 2.1.6 本地候选：媒体分发与音量

2026-10-26 补充安装记录：2.1.6 已合入有线微信语音兼容并在本车安装，发语音的电脑回放已通过。微信通话、完整重启后的音量恢复与通话听感仍待验证。详见 WIRED_MIC_2.1.6.md。以下保留原本地候选阶段的功能说明与验证边界。

本次从已经安装的 2.1.5 源码恢复，恢复前逐项核对了 75 份基础文件。2.1.5 的歌词过滤功能原样保留，之前取消的覆盖纠偏与歌词格式改写不包含在桥接中。后续按用户要求，在配套随心听 API 2 r2 中关闭了 CarPlay 的仪表广播，保留桌面信息；桥接 APK 本身未再改动。

## 上一曲／下一曲

沿用“接收 Key Mapper 的上一曲／下一曲”总开关。通话状态仍先决定接听、拒接、挂断或忽略；只有无通话时才查询音源。

- 随心听当前音源为在线音乐、蓝牙、USB 或收音机：明确发送给 `com.baidu.car.radio` 的 `NEXT` / `PRE`，由随心听处理该音源。
- 当前音源为 CarPlay 或未知，且唯一的 `DiPlay CarPlay` 媒体会话处于 `STATE_PLAYING`：发送到该会话。
- CarPlay 暂停、无会话或未连接：交给随心听当前音源。不会自动替用户选择其他音源；如果随心听仍选择 CarPlay，它也会按自己的 CarPlay 控制逻辑处理。
- 音源、会话、通话状态在查询过程中变化，按键过期，或通话／语音占用音频时取消本次操作。投递不确定时不自动重发，也不尝试另一个播放器。

匹配的随心听 API 2 提供公开的 `com.baidu.car.radio.MEDIA_REQUEST`，桥接通过有序 `get_state` 查询取得实时音源，无持续轮询。为兼容尚未更新的随心听 API 1，保留按键时只读 `carplay_source_v1.current_source` 的退路；一旦 API 2 已经响应，其临时失效会取消操作，不改用旧状态。

## 媒体音量记忆

入口：“媒体音量记忆与开机音量”。默认关闭，三种模式为关闭、记住上次媒体音量、每次开机使用指定音量。设置保存后本次音量不立即改变，下一次完整 Android 开机生效，需要保持桥接开机自启动。

只使用 `STREAM_MUSIC` 和普通的 `MODIFY_AUDIO_SETTINGS` 权限，不修改通话、铃声或闹钟流。运行期间通过媒体音量变化事件保存，避免持续轮询与开机初始默认值覆盖旧记忆；短时间的重复事件合并保存。

完整启动由 `boot_count` 标识，每次启动只恢复一次；服务重启或更新不会重复调整。启动后三分钟内等待接口有效、普通音频模式，并等待至少八秒初始化及最后一次音量变化后的一点五秒稳定期，随后恢复目标音量。通话或语音模式期间暂缓；超过启动窗口不再尝试。没有记忆值时保留原音量。休眠唤醒不作为一次完整开机处理，符合本次用户确认的“完整重启后恢复默认”的场景。

原车在该等待窗口后是否再次重置音量、平台是否允许 `STREAM_MUSIC` 控制实际扬声器音量，仍需实车完整重启验证。

## CarPlay 通话增益

这与媒体音量记忆分开，仍受原来“CarPlay 通话音量修正”开关控制，仅处理已适配 DiPlay 0.2.21 的 `telephony` PCM。

在 30 档范围内：

- 0 静音；1–6 的线性增益为档位 / 7。
- 7 为 1.0，即 0 dB，缓冲区保持原始字节。
- 8–30 按 dB 等间隔增加，增益为 `10 ^ (6 × (档位 - 7) / 23 / 20)`。
- 30 为约 1.995 倍，即 +6 dB。处理结果饱和限幅到 `[-32768, 32767]`，避免整数回绕。高电平素材仍可能削峰，需要听感验证。

旧的 7 / 30 为约 -12.64 dB。新运行时标记 `call-volume-3`，不会把旧音频代理误认为新版本；安装后旧 DiPlay 进程需要正常重开一次，不能在原进程里强拆正在运行的音频钩子。
