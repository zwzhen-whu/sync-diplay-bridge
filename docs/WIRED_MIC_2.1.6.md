# 2.1.6 有线微信语音兼容

在现有 2.1.6 的媒体分发、媒体音量记忆、通话增益基础上增加可关闭的有线输入兼容项。原版 DiPlay APK 不修改，VPN MTU 保持 1500。

入口为主界面的“有线 CarPlay 微信语音兼容”。默认关闭；开启/关闭从下一次录音生效，需要保持桥接运行并具备原有的本机调试接口。目前限定 Android 8.1/API 27、原版 DiPlay 0.2.21/code40 与已核对证书。其他车型、系统和 DiPlay 版本未验证。

仅当麦克风配置为有线 TUN 的 IPv6 链路、本次输入为单声道 LPCM 48 kHz、默认 20 ms 且手机没有明确指定 framesPerPacket 时，复制配置并将帧时长改为 10 ms。采样率、声道数、目标端口、加密密钥、payload type 均沿用 DiPlay 原配置；现有包处理自然得到每帧 960 字节、RTP 递增 480。加密后 IPv6 包长从 2004 字节降至 1044 字节。

无线、Opus、明确协商了帧长的流、其他采样率、双声道、音乐和提示音保持原处理。仅在流建立时处理配置，不复制麦克风音频，不全局放大或替换录音源，不发送手机暂停/重连请求。

控制器、根辅助程序与 map/audio 共用注入启动互斥；辅助程序与代理校验签名、版本、PID、进程启动时间和桥接代码。15 秒续租独立于电脑；服务退出或通信异常后代理对新流旁路，已建立录音到结束为止。每个原版进程仅附加一次，停用不热卸载 ART 方法。旧进程中的运行时版本不匹配时要求正常重开 DiPlay。

本轮临时试验中，用户确认微信发语音恢复；日志证实 speechrecognition/LPCM/48 kHz/10 ms，发出 388 包，无录音读取或发送错误，原版 PID 未变化。最初选择“两项都有声音”随后被用户澄清：尚未测试微信通话，只确认发语音正常。因此微信通话明确列为待验证，不能用语音消息结果替代。后续整合 APK 的安装与回测结果另见交付目录记录。

32 kHz 普通电话保持原分包。2.1.6 已有的 7 档原音量与最高 +6 dB 限幅继续保留，通话听感仍需自然使用时确认。
