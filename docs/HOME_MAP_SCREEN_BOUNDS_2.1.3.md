# 桌面地图拖动范围修正 2.1.3（本地候选）

旧版把屏幕宽度固定为 1920 px、底边固定为 618 px；浮窗顶部的最大 y 为 `618 − 浮窗高度`。例如高 340 px 时只能拖到 y=278。其他屏幕尺寸的车机因此可能出现向下拖不动、窗口部分超出屏幕或右侧范围不正确的问题。该限制在位置计算和旧应用设置迁移中均存在。

## 修改

- 使用实际承载浮窗的屏幕像素尺寸计算拖动范围，不再把 1920×720 或底部 102 px 当作所有车型的边界。
- 默认允许拖到物理屏幕边缘。新增“避开系统状态栏和底栏”开关，默认关闭；开启后按系统上报的可见区域限制拖动，系统上报不准确时可关闭此选项。
- 请求尺寸大于屏幕时临时缩小浮窗，保证完整窗口能够放入屏幕；偏好中的请求尺寸保留，恢复较大屏幕后可重新使用。
- 显示尺寸、配置和可见区域变化时更新边界；只响应系统事件及返回桌面，不新增固定周期轮询。触摸移动和每帧绘制路径不查询系统窗口区域。
- 系统临时无法返回有效边界时保留上次成功的边界。空的或屏幕外的可见区域不作为零尺寸边界使用。
- 自动适配不写回裁剪后的 x/y/宽高；只有手动拖动保存新的位置。旧应用迁移保留合法位置，待 UI 进程读取实际屏幕后再约束，避免提前丢掉大屏上的坐标。
- “跟随桌面滑动”仍可开关且默认关闭；关闭跟随后可手动拖动定位，滚动量不覆盖保存的位置。
- DiPlay 的 1280×480 地图源、解码脚本、虚拟显示生命周期、通话音量处理和原有按键功能未改写。

系统栏选项依据 Android 上报的可见区域；未作为系统栏上报的厂商自定义气候面板无法仅凭通用接口保证识别。关闭该选项后，拖动范围直接使用屏幕边缘。

## 本地验证

2026-10-26：26 组回归和完整 Android 编译通过，原证书 v2/v3 签名通过。新增 `MapViewportTest` 83 项，迁移检查增为 30 项，原跟随检查 78 项继续通过。

模拟尺寸：1920×720、1280×720、1920×1080、2560×1440、800×480、320×200、720×1280。覆盖四个边缘、非零系统栏偏移、关闭避让恢复全屏、超大窗口适配、小屏恢复大屏、无效可见区域回退及跟随裁剪。

关键回归：1920×720 屏幕上高 340 px 的窗口可到 y=380；1920×1080 上可到 y=740，不再受旧 618 底边限制。可选系统可见区域确实为 1920×618 时，仍按用户开启的避让策略限制到 y=278。

未连接、操作或安装车机；没有本地 Android 模拟器，未做 Android UI 运行检查。其他车型的实际屏幕指标、触摸坐标、系统可见区域及最终显示效果仍需对应车辆验证。此版本修复通用位置边界，不代表 DiPlay 协议、系统版本或桌面滚动监听已经适配所有车型。
